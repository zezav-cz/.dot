# Ubuntu Server + Sway Bootstrap (Phase 1)

**Status:** Phase 1 complete — verified on KVM 192.168.124.68 2026-08-11
**Date:** 2026-08-11

## Context

The `.dot` repo currently targets Fedora Sway Spin, installed via a Python
installer (`install.py` + `installer/`). The goal is to migrate the daily
driver to Ubuntu Server as a base, with Sway installed manually on top
(no desktop spin), and eventually to replace the Python installer with
Ansible.

That end goal is too large for one spec, so it's split into three
independent, sequential sub-projects:

1. **Bootstrap Sway on Ubuntu Server** (this spec) — prove the base layer
   works and figure out what Ubuntu actually needs that Fedora's spin gave
   us for free.
2. **Ansible for Ubuntu** — codify phase 1's findings plus the rest of
   `install.py`'s behavior (stow, shell, apps, fonts) as Ansible playbooks
   targeting Ubuntu.
3. **Ansible for Fedora too** — extend the same playbooks to cover Fedora,
   and retire the Python installer.

This document covers phase 1 only.

## Test environment

- KVM at `192.168.124.68`, user `jan`, Ubuntu 26.04 LTS Server (minimal
  install: 720 packages, no desktop/session-manager components).
- Confirmed via recon: virtio GPU (simple KMS, no driver needed),
  `systemd-networkd` active (not NetworkManager), no `seatd` (relies on
  `systemd-logind`, which is present), no `sway`/`pipewire`/greeter
  installed.
- This KVM is a throwaway testbed. The real target is eventually a laptop,
  but WiFi/NetworkManager/power-management concerns are explicitly
  out of scope for phase 1 — they belong to a later, laptop-specific pass.

## Goal / success criteria

Boot the KVM → `tuigreet` login prompt on tty1 → log in → Sway session
starts with:

- A working `foot` terminal launched via `$mod+Return`.
- Correct keyboard layout (`us,cz` with `alt_shift_toggle`/`grp:switch`).
- Touchpad-equivalent input settings applied (harmless no-op on this VM,
  but config must load without error).
- Window management keybinds functional: focus/move by direction, resize
  mode, workspace switching, moving workspaces between outputs.

Out of scope for phase 1: waybar, swaync, gammastep, kanshi, theming,
tailscale, screenshot/recording tools, wallpaper. These return in phase 2
once they're part of the Ansible-managed package set.

## Packages (apt)

- `sway`
- `foot`
- `greetd`, `greetd-tuigreet`
- `polkit-kde-agent` (or equivalent polkit authentication agent — the
  polkit libraries are present on the image but no agent is running)
- `xwayland`
- `fonts-noto` as a fallback font (the repo's Nerd Font isn't installed
  yet; `appearance.conf`'s font line will silently fall back to a
  available font — not fatal, just not the intended look)

## Login flow

Configure `greetd` with `tuigreet` as the greeter, `command = "sway"` in
`/etc/greetd/config.toml`. This replaces the currently-inactive default
`getty` on tty1. On successful login, `tuigreet` execs `sway` directly.

## Config strategy

The repo's top-level `stow/sway/.config/sway/config` is **not** used
as-is for this phase. It contains:

- `exec` lines for `gammastep`, `swaync`, `kanshi`, `tailscale systray`,
  a Slack autostart check, and theme-watcher scripts — none of which are
  installed in phase 1. These failures are non-fatal (Sway logs and
  continues) but are noise this phase doesn't need.
- One Fedora-specific line:
  `include '$(/usr/libexec/sway/layered-include ...)'` — part of
  Fedora's sway packaging (layered config merging from `/usr/share` and
  `/etc`). This path does not exist on Ubuntu. **Flagged as a known
  portability gap** to resolve in phase 2, not phase 1.

The following files under `stow/sway/.config/sway/config.d/` and
`modes.d/` *are* portable as-is (no distro-specific paths, and any
commands they reference — `rofi`, `swaylock`, `grim`, `slurp`, `swappy`,
`~/.local/bin/screenrecord` — are only invoked on keypress, so their
absence is harmless unless actually triggered):

- `config.d/variables.conf`
- `config.d/keymaps.conf`
- `config.d/appearance.conf`
- `config.d/inputs.conf`
- `config.d/custom-keymap.conf`
- `modes.d/resize.conf`

`stow/sway/.config/sway/outputs` is **not** used — it holds the actual
laptop's panel geometry (`eDP-1`/`HDMI-A-1`, generated by `nwg-displays`),
meaningless on a single-virtio-output VM. Sway auto-detects instead.

For phase 1, a minimal top-level `sway/config` will be hand-written for
the test that sources the six portable files above, with no wallpaper or
autostart `exec` block.

## Getting the repo onto the KVM

The local working tree has substantial uncommitted changes (including
sway config edits) not yet pushed to `origin`. The repo will be
transferred via `rsync` from the local machine rather than `git clone`,
so the test reflects the actual working tree, not stale `origin`.

## sudo handling

`sudo` on the KVM currently requires a password on every invocation. For
this disposable, single-user test VM, a `NOPASSWD` sudoers entry for
`jan` will be added (scoped to this box only) to keep the bootstrap loop
fast. This is a security-relevant change but acceptable for a throwaway
test machine under the user's control.

## Verification

No physical display access to this VM — verification is command-line
and log-based, via SSH, not visual:

- `systemctl status greetd` is active.
- A `sway` process is running under the logged-in session.
- `swaymsg -t get_inputs` shows the configured keyboard layout.
- `swaymsg -t get_outputs` shows the virtio output auto-detected and
  enabled.
- `journalctl` / Sway's log shows no fatal errors (non-fatal `exec`
  warnings for anything intentionally unconfigured are expected and
  fine).

## Open items carried to later phases

- Fedora-specific `layered-include` line in the main sway config needs a
  portable equivalent (or distro-conditional handling) before phase 2.
- WiFi/NetworkManager and laptop power management are deferred until the
  real laptop migration.
- Nerd Font installation is deferred to whenever fonts are ported to
  Ansible (phase 2), matching `install.py`'s existing font step.
